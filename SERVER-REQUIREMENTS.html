t-scan — Server Requirements

Hardware, software and network needed to run the complete application: web interface, API, AI assistant, sentiment analysis and content ingestion. Figures below are measured from the working deployment, not estimated from vendor documentation.

Non-negotiable

A dedicated NVIDIA GPU is required. The AI assistant and the risk-scoring engine both run language models locally. Without a GPU, a question that answers in about one second takes several minutes, and bulk sentiment analysis of incoming posts becomes impractical. This is the single requirement that cannot be worked around.

Database

This is the decision that needs making before the server is ordered, because it affects where the data lives.

Decision required

The application currently uses MongoDB Atlas, a managed cloud database, on a shared tier that permits only three search indexes. The system has seven collections that would benefit from one, so four currently run on a slower fallback.

Two options, and they are not equivalent:

OptionWhat it meansConsideration
MongoDB Atlas M10+
Simplest		 Dedicated managed cluster. Lifts the index limit, adds automatic backup and monitoring. Data resides in the cloud provider's data centre. The server needs permanent outbound internet access. Requires the office's public IP to be allowlisted.
Self-hosted MongoDB
Data stays on site		 Database runs on the same server or an adjacent one. All data remains within the department's network. Important: the meaning-based search used by the AI assistant relies on a feature of Atlas. Moving on-premises requires either MongoDB Enterprise with Atlas Search, or a separate vector search component. This is engineering work, not a configuration change — allow time for it.

If data residency is a requirement from the department's side, raise it now rather than after the server is provisioned.

Capacity

The language model is the limiting factor, not the database or the network.

GPU memoryConcurrent assistant usersSentiment processing
8 GB5–8 simultaneous questionsShares the same model; slows while the assistant is busy
16 GB15–20 simultaneous questionsCan run its own model independently
24 GB25–35 simultaneous questionsIndependent, with room for a larger, more accurate model

Officers browsing dashboards, alerts and reports do not consume GPU time — only AI assistant questions and the scoring of newly collected posts do. A deployment with 200 officers where 10 are asking questions at any moment sits comfortably within the 16 GB figure.

Before the server is handed over

  • NVIDIA driver and CUDA 12 installed, and nvidia-smi reports the GPU
  • Python 3.12 and Node.js 20 LTS installed
  • Outbound HTTPS confirmed to the database and data providers
  • Static public IP assigned and allowlisted on the database, if cloud-hosted
  • Internal DNS name or fixed IP for the server, so officers have one address
  • TLS certificate for that address
  • Services configured to start automatically after a reboot
  • Backup arrangement agreed — automatic with a managed database, to be set up if self-hosted
  • Administrator account on the server for installation and later maintenance

How the figures were obtained

Model memory, disk usage, database size and record counts were measured directly on the running installation. CPU, RAM and storage recommendations add headroom to what that installation uses, since it is a development machine running one tenant. The concurrency figures are projections from the measured per-question cost and the memory a model occupies; they have not been load-tested, and should be treated as planning guidance rather than guarantees.
